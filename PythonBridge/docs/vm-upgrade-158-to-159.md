# VM release - 13 November 2026

Use this release with the existing VM database updated through migration **157**.
Run [upgrade_158_to_159_vm.sql](../sql/deploy/upgrade_158_to_159_vm.sql), which combines:

| Migration | Change |
| --- | --- |
| 158 | Opportunity header Estimate Delivery Date; copies a unique legacy item date and leaves conflicting dates blank |
| 159 | Packaging and Recipe Sales review metadata and packaging Awaiting Sales transitions |

The bundle is rerunnable and retains the source migrations exactly. It is **not atomic**: each migration retains its own transaction boundaries. It stops on error in SQLCMD mode. Existing published results are preserved; existing manager-approved recipe sheets become Sales accepted when the Sales status column is first added. New responses publish only after manager approval and acceptance by the original request creator or Admin. Returns preserve current accepted Opportunity results.

## VM deployment

1. Back up the application database and retain the current API and compiled UI folders.
2. Stop the API service and all workers.
3. Select the existing application database. Run the combined script in **SSMS SQLCMD mode** or `sqlcmd -b -S YOUR_SERVER -d YOUR_DATABASE -i upgrade_158_to_159_vm.sql`. Do not run against a system database. If the VM is older than 157, apply the preceding bundles first.
4. Confirm `Upgrade 158-159 verified. Deploy matching application files before restarting.` If an error occurs, resolve it and rerun before starting the updated API.
5. Copy the complete **core/** and **webapp/dist/** from this commit. Replace the old dist folder with the matching build, including new files. Preserve VM environment settings, credentials, service configuration and attachment storage.
6. Restart the API service/all workers. Hard-refresh browsers with Ctrl+F5.
7. Check the delivery date header, Packaging/Recipe manager approval followed by Sales acceptance/return, and TCB retained results. Check Recipe Sheet Details/Full views, repeated ingredient aggregation and compact green tables.

No extra SQL is required for Recipe Details levels: they are captured in the existing calculation JSON and carried into revisions. TCB Recipe Info now always shows Seasoning and Seasoning Ratio; current Oil/Salt values are not merged. Historical stored calculations are retained. Pallet master saves no longer validate unrelated saved response load counts. See the linked feature notes for scope.

## Validation

The bundle contract verifies exact ordered migration embedding, safe target guards and final schema/procedure checks. A desktop test applies the embedded migrations twice inside a rollback transaction and compares deterministic hashes of business and master tables before/after. Test fixtures are not deployed.

The bundle generator never connects to a database. Regenerate with `scripts/Build-VMUpgrade158To159.ps1`. Checksums are generated by `deployment/company/New-ReleaseChecksums.ps1`.

Rollback after business use requires coordinated database/application recovery. Copying the old API alone does not undo accepted data or schema changes.
